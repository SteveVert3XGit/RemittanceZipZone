Hot Zone Algorithm — Revised

Zone logic is now purely WU-internal: too many WU = saturation, demand with no WU = expansion

Revised Zone Logic

// EXPANSION — opportunity signal exists, WU is absent
if demandScore(cluster) > threshold
  AND count(WU within 0.5mi) == 0
  → EXPANSION ZONE — "Underserved, open here"

// SATURATION — too many WU locations cannibalizing each other
if count(WU within 0.4mi of another WU) >= 2
  → SATURATION ZONE — "WU oversaturated, review footprint"

// Competitor presence (MoneyGram, Ria) shown on map for context only
// — informs expansion confidence, does NOT drive zone classification

What Changed vs Previous Version

BEFORE (removed)
Saturation = 3+ remittance providers (WU + MG + Ria) within 0.5mi

Problem: flags WU locations as saturated because competitors are nearby — not actionable for WU decision-making
NOW (correct)
Saturation = 2+ WU stores within 0.4mi of each other

WU cannibalizing its own agents — directly actionable: which WU to consolidate

Demand Score Inputs (unchanged)

🟣 Ethnic Grocery / Supermarket +3
🟢 Financial Services (check cash etc) +2
🩷 Dollar Stores +1
🔵 Laundromats +1
Cluster threshold: demandScore ≥ 4 within 0.3mi radius triggers evaluation
