Design Section 2 of 4: Hot Zone Algorithm

Zones are computed from data — not hand-drawn. Two zone types signal opposite recommendations.

How Zones Are Computed

// Step 1 — score each demand signal location
demandScore(loc) = ethnic_grocery(+3) + financial_svc(+2) + dollar_store(+1) + laundromat(+1)

// Step 2 — find clusters within 0.3 mile radius
cluster = group demand signals where distance < 0.3mi

// Step 3 — score remittance saturation at cluster centroid
saturationScore = count(WU + MG + Ria within 0.5mi of centroid)

// Step 4 — classify zone
if demandScore > threshold AND saturationScore < 2 → EXPANSION zone
if saturationScore ≥ 3 AND providers clustered < 0.25mi → SATURATION zone

Zone Visual Language

Expansion Opportunity
• Green radial gradient ellipse
• High demand signal density
• Low/no remittance coverage
• Label: "Underserved — Open Here"
Saturation Risk
• Red radial gradient ellipse
• 3+ remittance providers nearby
• High competitive overlap
• Label: "Oversaturated — Review"
