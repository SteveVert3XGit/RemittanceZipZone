Design Section 1 of 4: Data Model & Pin Categories

Every store is one JS object. Pins render from the array — no hardcoded SVG pins.

Store Object Shape

const stores = [
  {
    id: "wu_001",
    category: "western_union",  // drives pin color + toggle
    role: "primary",          // "primary" | "demand_signal"
    name: "Western Union at Check City",
    address: "1234 NW 7th Ave, Miami FL 33147",
    lat: 25.8234, lng: -80.2156,
    rating: 4.2, reviews: 38,
    hours: "Mon–Sat 9am–7pm",
    notes: "Inside Check City, high foot traffic"
  }
];

Pin Categories & Colors

REMITTANCE PROVIDERS (Primary)
Western Union — Gold
MoneyGram — Navy Blue
Ria Money Transfer — Red
DEMAND SIGNALS (Context)
Financial Services — Green
Ethnic Grocery / Supermarket — Purple
Dollar Stores — Pink
Laundromats — Cyan

Remittance pins are larger (14px radius). Demand signal pins are smaller (8px) — present but visually secondary.

Data Sourcing for Demo

Since all_stores_master_v3.csv covers Boost Mobile, not remittance — locations for 33147 will be sourced from Google Places API research and hardcoded into the JS data array for the demo. The data structure is the same whether hardcoded or dynamically loaded, so swapping to a live API later is a clean upgrade path.
